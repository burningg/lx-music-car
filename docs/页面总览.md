# 页面总览（重设计用）

基于 `lx-music-mobile` v1.9.2（React Native 0.73）实际代码整理。一页一节，讲清"这是什么页面、长什么样、主要能点什么、重设计要注意什么"。

> 详细到每个控件的清单在 `docs/ui-audit/`（需要时再翻，日常看这份就够）。

---

## 10 秒看懂

- 全 App 只有 **4 个独立页面**：主页、播放详情、歌单详情、评论。
- "主页"里装着 **5 个标签页**：搜索 / 歌单 / 排行榜 / 我的 / 设置 —— 靠**左右滑动**切换，不是底部栏。
- **横屏和竖屏是两套完全不同的界面**（横屏宽高比 > 1.2 自动切换），不是同一套放大缩小。
- 全局只有 **16 套主题**、一套配色令牌；弹层是**原生 Alert 和原生 Toast**，改不了样式。
- 页面里的播放条（底部迷你播放器）常驻在主页与歌单详情之上。

---

## 1. 启动 / 全局背景

**是什么**：App 启动后先铺一层全局背景，再挂主页。
**结构**：主题背景图，或当前歌曲封面高斯模糊 + 76% 遮罩；所有页面共用这一层。
**主要控件**：无（纯背景层）。
**重设计注意**：改这里会影响**所有页面**的对比度；深色主题下尤其要验文字可读性。

---

## 2. 主页 · 搜索

**是什么**：默认落地页，搜索歌曲/歌单/歌手/专辑。
**结构**：顶栏（来源切换 + 输入框 + 类型切换）→ 内容区；内容区分三态：空关键词、输入建议、搜索结果。
**主要控件**：

| 区域 | 能点什么 |
|---|---|
| 顶栏 | 来源下拉、输入框、类型标签（单曲/歌单/歌手/专辑） |
| 空态 | 热搜词、搜索历史（可清空） |
| 输入建议 | 浮层候选词，点即搜 |
| 结果列表 | 行点击播放、行尾"更多"菜单、**长按进多选**、底部多选工具条、下拉刷新、上拉加载 |

**重设计注意**：
- 类型切换器其实**挂在上页顶栏**，和搜索页不是父子关系，靠全局事件通信 —— 换位置要连带改事件。
- 搜索历史只在"真正提交搜索"时写入，别把搜索改成独立按钮而不复用回调。

---

## 3. 主页 · 歌单广场

**是什么**：在线歌单浏览，按标签/排序筛选。
**结构**：顶栏四段（排序：最新/最热 · 来源 · 标签入口 · 打开歌单）→ 标签抽屉 → 歌单网格。
**主要控件**：

| 区域 | 能点什么 |
|---|---|
| 顶栏 | 排序切换、来源下拉、打开标签抽屉、"打开歌单"按钮 |
| 标签抽屉 | 标签分组、点选标签 |
| 网格卡片 | 点击进歌单详情（带图片**共享元素转场**）、下拉刷新、上拉加载 |
| 打开歌单弹层 | 粘贴链接/输入识别 |

**重设计注意**：卡片封面带转场锚点，换图片组件或加裁剪层会让转场**静默失效**（不报错）。网格列数变化会重建整个列表、滚动位置归零。

---

## 4. 主页 · 排行榜

**是什么**：各音乐平台榜单。
**结构**：竖屏 = 榜单名 + 来源 → 榜单抽屉 → 歌曲列表；横屏 = 左侧常驻榜单栏 + 右侧歌曲列表。
**主要控件**：来源下拉、榜单抽屉（切榜单）、行点击播放、行尾更多、长按多选、收藏到我的列表。
**重设计注意**：切来源会连着"拉榜单 → 取第一首 → 刷新标题 → 拉歌曲"四步，少一步标题和歌曲就对不上。

---

## 5. 主页 · 我的音乐（歌单管理）

**是什么**：本地歌单与歌曲的管理中枢，最重的页面。
**结构**：歌单列表（抽屉/侧栏）+ 歌曲列表（主区）；歌曲列表上有标题条、搜索条、多选条。
**主要控件**：

| 区域 | 能点什么 |
|---|---|
| 歌单列表 | 点选歌单、**长按/更多**（重命名 · 排序 · 导入 · 导出 · 移除）、新建歌单 |
| 标题条 | 当前歌单名、歌曲数、排序入口 |
| 搜索条 | 歌单内搜索歌曲 |
| 歌曲行 | 播放、行尾更多（播放/下一首播放/收藏/换源/信息/移除）、**长按进多选** |
| 多选条 | 选择单曲/范围/全选/取消 + 批量更多 |

**重设计注意**：
- **没有拖动排序、没有滑动删除、没有播放全部** —— 这三样当前不存在，设计稿别画。
- 排序实际是两个弹层：字段排序、以及"输入序号"调整位置。
- 确认框有**两套**（自绘 + 系统原生），按钮语气四种，重设计前先统一，否则永远"看着没改完"。

---

## 6. 主页 · 设置（10 个子页，110 项）

**是什么**：所有偏好设置。
**结构**：
- 竖屏：**10 个子页纵向堆在一个滚动列表里**（没有分组导航）。
- 横屏：左侧 22% 导航栏 + 右侧内容。
**子页**：基本设置(46) · 播放(15) · 桌面歌词(23) · 搜索(2) · 列表(5) · 数据同步(3) · 备份恢复(2) · 其他(7) · 软件更新(1) · 关于(6)。
**控件类型**：开关 35 · 单选 27 · 滑块 4 · 按钮 11 · 输入 2 · 色板/跳转 31。

**重设计注意**：
- 只有 **46%** 的条目走了统一封装，剩下 59 项是各文件复制的裸复选框、自绘色板、硬编码文字链接 —— 只改封装会出现"两种复选框"。
- 竖屏加分组导航要做，但当前页码状态是**全局单例**，横竖屏切换容易丢。
- 主题色板默认折叠只显示 1 项，16 套主题被藏着，是信息架构最大问题。

---

## 7. 播放详情（竖屏）

**是什么**：全屏播放页，封面 + 歌词 + 控制。
**结构**：顶栏（返回/标题/定时退出）→ 封面区（共享元素转场）→ 歌词区（可切到进度播放行）→ 进度条 → 控制键（上一首/播放/下一首）→ 更多按钮组 → 设置弹层。
**主要控件**：播放/暂停、上下曲、进度条拖动 seek、歌词滚动（拖动锁定 3 秒）、更多（桌面歌词/评论/添加歌单/播放模式/定时退出）、设置弹层（字号/对齐/倍速/音量/进度显示）。
**重设计注意**：
- 歌词滚动偏移和**行高测量**强绑定，改行高/行距/翻译行显隐 → 歌词越走越偏（最难回滚）。
- 进度条靠实测宽度算点击位置，加内边距/圆角胶囊/换容器 → seek 静默跳错位。
- 封面转场锚点与顶栏高度硬绑定，加裁切或旋转会闪跳。
- **没有**点击歌词跳转、没有"上滑"（是左右滑）、没有封面旋转动画。

---

## 8. 播放详情（横屏）

**是什么**：同一业务的车机/横屏布局，**独立实现**。
**结构**：左列（封面 + 歌曲信息 + 控制键）/ 右列（歌词）；顶栏含桌面歌词、评论；定时退出按钮被挪到左列。
**主要控件**：同竖屏，但"更多"能力归属**正好相反**（竖屏在顶栏的，横屏在左列）。
**重设计注意**：和竖屏不共享布局代码，歌词组件 95% 重复 —— 要改就得改两遍，或先抽公共组件。

---

## 9. 迷你播放条

**是什么**：主页、歌单详情底部常驻的播放条。
**结构**：封面 + 歌名/歌手 + 播放键 + 一条绝对定位的细进度条。
**主要控件**：点击进播放详情、播放/暂停、可拖动进度。
**重设计注意**：进度条是叠在整条上的绝对层，键盘弹出时整条会消失（现有行为）。

---

## 10. 歌单详情

**是什么**：点开某个歌单后的页面。
**结构**：顶栏（返回 + 封面转场 + 歌名/作者/播放量）→ 操作栏（播放全部等）→ 歌曲列表。
**主要控件**：返回、播放全部、收藏、行点击播放、行尾更多、长按多选。
**重设计注意**：封面是转场终点，和列表卡片的锚点必须成对；播放量/作者是**硬编码颜色**，深色主题下对比不足（既有缺陷）。

---

## 11. 评论

**是什么**：当前歌曲的评论。
**结构**：顶栏（返回 + 标题 + 热门/最新 标签）→ 评论列表（楼层、点赞）+ 左右滑动切换热门/最新。
**主要控件**：返回、标签切换（与左右滑动双向同步）、点赞。
**重设计注意**：标签与滑动页双向同步，楼层数据是空依赖缓存 —— 换成新列表要保住同步关系。

---

## 12. 全局弹层与反馈

**是什么**：所有页面共用的浮层体系。
**层级**：Toast＜菜单＜弹窗＜抽屉＜整页转场。

| 类型 | 现状 | 能否改样式 |
|---|---|---|
| Toast 轻提示 | Android 原生 | ❌ 不能 |
| 确认框/提示框 | 系统 Alert | ❌ 不能 |
| 应用内确认框 | 自绘 | ✅ |
| 菜单 / 下拉 / 弹窗 / 弹层 | 自绘，全部落到同一个 Modal | ✅ 改一处全站生效 |
| 抽屉 | 自绘（含原生补丁） | ⚠️ 改结构易"第二次打不开" |

**重设计注意**：品牌化的 Toast 和确认框，当前技术路径上做不到 —— 要做得自绘替换，属于改逻辑，需单独立项。

---

## 13. 导航模型（改结构前必读）

| 层 | 实现 | 重设计影响 |
|---|---|---|
| 独立页面 | 原生导航 push（主页 / 播放详情 / 歌单详情 / 评论） | 可换转场动画，但共享元素锚点是逻辑 |
| 5 个标签页 | 屏内左右滑动（PagerView），索引写死 0–4 | 换底部栏/抽屉，要同时改滑动回写与懒加载 |
| 3 个系统弹窗 | 原生 Modal（版本更新 / 协议 / 同步模式） | 受原生壳限制 |
| 抽屉导航 | 自绘 | 有 RN 原生补丁，动前先读代码 |

**核心约束**：标签页**不是路由**，没有地址、没有历史；页面顺序、`key`、索引三者绑定，"把 Tab 改成底部栏"实际是重写导航。

---

## 一页纸结论

| 你想做什么 | 可行性 |
|---|---|
| 换配色、排版、卡片/行样式、弹层内容布局、图标 | ✅ 安全 |
| 重排信息架构（在不动标签页索引的前提下） | ✅ 可行 |
| 设置中心视觉统一 | ✅ 但需先补 3 个封装（否则 59 项保持旧观感） |
| 品牌化 Toast / 确认框 | ❌ 需改逻辑 |
| 拖动排序 / 滑动删除 / 播放全部 / 封面旋转 / 歌词点击 | ❌ 当前不存在，属新功能 |

**工作量提醒**：每个页面都要出**两张图**（竖屏 + 横屏）。建议先做设置中心（最好量），最后做播放详情（19 处手势/动画耦合，风险最高）。

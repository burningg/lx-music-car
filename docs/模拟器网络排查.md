# Android 模拟器配置音源后无法播放

## 已确认的一种原因：模拟器 DNS 异常

如果播放页长时间显示 `Getting music link...`，同时封面和歌词也无法加载，
不要仅凭“音源已初始化”就认定音源接口可用，也不要直接修改播放器。

本次排查（2026-11-06，`Small_Desktop` 模拟器）的证据：

- 音源脚本能够发起 `musicUrl` 请求，但请求报 `Network request failed`。
- 模拟器可以访问公网 IP，解析普通网站域名却报 `unknown host`。
- 默认 DNS 地址为模拟器内部转发地址 `10.0.2.3`；直接查询公网 DNS 可以收到响应。
- 使用显式 DNS 冷启动同一个模拟器后，域名解析和音源请求恢复。
- 原有音源返回有效播放链接；Android 媒体会话进入 `PLAYING`，播放进度推进，封面和歌词恢复。

这是开发环境问题，本次没有修改播放逻辑、音源脚本或应用网络安全配置。

## 1. 区分断网、DNS 异常与音源服务故障

如果连接了多台设备，请在 `adb` 后加 `-s <设备序列号>`。

```sh
adb devices -l
adb shell ping -c 1 -W 3 223.5.5.5
adb shell ping -c 1 -W 3 www.baidu.com
adb shell dumpsys connectivity
adb shell settings get global http_proxy
adb shell settings get global private_dns_mode
adb shell settings get global private_dns_specifier
```

- IP 可达、域名出现 `unknown host`：优先排查 DNS。
- 域名能解析，但 ping 不通：不能单凭这一点判断断网，目标可能禁用 ICMP。
- 普通网络请求正常，只有音源失败：继续检查音源响应、超时、证书或服务可用性。
- 宿主机浏览器正常不代表模拟器正常，模拟器不一定继承宿主机代理和 DNS 行为。

## 2. 使用显式 DNS 冷启动模拟器

先在 Android Studio 的 Device Manager 中停止目标模拟器，再启动同一个 AVD。
macOS 默认 SDK 路径示例：

```sh
SDK="${ANDROID_HOME:-${ANDROID_SDK_ROOT:-$HOME/Library/Android/sdk}}"

"$SDK/emulator/emulator" -list-avds
"$SDK/emulator/emulator" \
  -avd Small_Desktop \
  -dns-server 223.5.5.5,119.29.29.29 \
  -no-snapshot-load
```

将 `Small_Desktop` 换成实际 AVD 名称；DNS 地址也可以换成当前网络允许使用的服务器。
`-no-snapshot-load` 只跳过快照进行冷启动，**不会清除应用数据或已导入音源**。
不要使用 `-wipe-data`，也无需卸载应用。

这些 DNS 参数作用于本次启动。以后从 Android Studio 默认启动时，如果问题复现，
应再次用上述命令启动，而不是把 DNS、代理或固定 IP 写进应用代码。

如果只是日常使用而不需要热更新，建议按 [Android 启动与打包](Android启动与打包.md)
运行 `npm run android` 安装独立版；独立版不依赖 Metro，也不需要下面的端口转发。

开发调试版还需恢复 Metro 端口转发，并确保项目中的 `npm start` 正在运行：

```sh
adb wait-for-device
adb reverse tcp:8081 tcp:8081
adb shell am start -n cn.toside.music.mobile/.MainActivity
```

## 3. 复测播放

再次检查域名解析，然后在应用中播放歌曲，确认播放时间持续增长、封面和歌词加载。
也可以检查 Android 媒体会话：

```sh
adb shell dumpsys media_session
```

应在 `cn.toside.music.mobile/TrackPlayer` 会话中看到 `state=PLAYING(3)`，
而不只是音源初始化成功或停留在获取链接状态。

若仍失败，可在本机检查 `adb logcat`。音源日志可能含完整请求 URL、签名或令牌，
分享日志前请先脱敏。
